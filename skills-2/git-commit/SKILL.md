## Instructions

1. Run `git status` to see untracked and modified files
2. Run `git diff` (staged + unstaged) to understand all changes
3. Run `git log --oneline -5` to see recent commit message style in the current repository
4. Based on the changes, draft a commit message following the rules below
5. Stage only the relevant changed files by name (do NOT use `git add -A` or `git add .` indiscriminately)
6. Create the commit using `git commit -m "<type>: <description>"` (ensure NO trailer or extra footer is attached)
7. Show the result with `git log --oneline -1`
8. Push to remote ONLY IF the user explicitly requested push/提交并推送

## Commit message rules

- **语言**：始终使用中文撰写提交信息。
- **提交类型（Conventional Commits）**：
  - `feat:` 新增功能、知识点代码或新章节
  - `docs:` 编写或更新文档、笔记、路线图、规则（如 AGENTS.md、README.md 等）
  - `fix:` 修复代码缺陷、错别字或语法错误
  - `refactor:` 代码重构（不增加新功能也不修改 bug）
  - `test:` 新增或修改测试用例
  - `chore:` 构建配置、辅助工具或依赖项微调
- **简单明了、说明清晰**：清晰准确说明本次改动涉及的核心内容与模块，直奔主题，避免模糊泛化的描述（如“修改代码”、“更新文件”）。
- **结构精炼**：标题行简明扼要（一般控制在 50 字以内），清楚说明改动了什么；如需补充说明背景或多项细节，可在正文分条简述，保持清晰易读。
- **🚫 严禁 AI 署名/尾注（最高红线）**：
  - **绝对严禁**在提交信息中包含任何 `Co-Authored-By` 署名（例如 `Co-Authored-By: Claude Opus ... <noreply@anthropic.com>`、`Co-Authored-By: Gemini ...` 等）。
  - **绝对严禁**添加任何 AI 宣传标语、自动化生成标记或助手署名（如 `Generated by ...`、`Assisted by ...` 等）。
  - **提交信息必须 100% 纯净**，只包含改动说明本身。
- **安全与推送**：
  - 严禁提交敏感凭证、`.env` 文件、密钥或临时测试数据。
  - 未经用户明确指示，默认不执行 `git push`；用户明确说明 push 时方可执行。

### 示例参考

- **❌ 错误示例（过于笼统）**：`更新代码`、`修复一些问题`
- **❌ 错误示例（包含 AI 署名/尾注）**：
  ```text
  docs: 明确学习者 Spring Boot 零基础，强化仔细认真讲解要求

  Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>
  ```
- **✅ 正确示例（功能新增）**：`feat: 新增 HelloController 控制器及 /hello 测试接口`
- **✅ 正确示例（文档更新）**：`docs: 完善第 1 章学习笔记并更新路线图`
- **✅ 正确示例（缺陷修复）**：`fix: 修复 UserService 依赖注入为 null 的异常`
